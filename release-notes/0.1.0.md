Quartzio is a Gantt chart library in two packages: `@quartzio/gantt`, a headless engine in TypeScript with no
dependencies and no DOM, and `@quartzio/gantt-react`, a React component on top of it. The engine does the
scheduling, the layout and the interaction; the component only draws. This first release covers what a project plan
needs day to day: tasks in a tree, dependencies, working-time calendars, dragging, editing, menus, the keyboard and
undo.

## Highlights

### A working chart with no setup

```bash
npm install @quartzio/gantt-react @quartzio/gantt
```

```tsx
import type { ProjectInput } from '@quartzio/gantt';
import { Gantt } from '@quartzio/gantt-react';
import '@quartzio/gantt-react/styles.css';

const plan: ProjectInput = {
  settings: { timeZone: 'Europe/Oslo' },
  tasks: [
    { id: 1, name: 'Design', startDate: '2026-10-05', duration: 3 },
    { id: 2, name: 'Build', duration: 10 },
  ],
  dependencies: [{ id: 1, from: 1, to: 2 }],
};

export function App() {
  return <Gantt defaultData={plan} style={{ height: 500 }} />;
}
```

Bars can be dragged, resized and linked, cells and bars edited with a double-click, tasks added and indented from
the right-click menu, and every change undone with Ctrl/Cmd+Z.

### Scheduling in working time

Durations are working time in the project calendar: `duration: 3` is three working days, so a task that starts on
a Friday ends on Tuesday. Automatically scheduled tasks start as soon as possible after the project start and their
predecessors, with all four dependency types (`'FS'`, `'SS'`, `'FF'`, `'SF'`) and lag. Parents span their children,
and `manuallyScheduled` tasks keep their own dates. The computed dates are written back into your data in the same
change, so the data you get back always holds the dates the chart shows.

Calendars have working hours per weekday and exceptions for holidays, and everything that depends on the wall clock
follows the project's `settings.timeZone`, daylight saving time included.

### Your data, your way

Keep the data in the chart with `defaultData`, or own it with `data` and `onChange`. Every change comes with the full
project as plain JSON, a patch with its inverse, and where it came from:

```tsx
const onChange = (change: GanttDataChange) => {
  setData(change.data);
  // 'load' is the computed dates written back into loaded data, not an edit.
  if (change.source !== 'load') setUnsaved(true);
};

<Gantt data={data} onChange={onChange} />;
```

Change the plan from code with a transaction. It is one change: one undo step and one `onChange`.

```tsx
gantt.current?.transact((tx) => {
  const task = tx.tasks.add({ name: 'Inspection', duration: 1 });
  tx.dependencies.add({ from: 2, to: task.id });
});
```

## New

**Data and scheduling**

- Tasks nested with `children` or flat with `parentId`; dependencies with `type`, `lag` and `lagUnit`; calendars with
  weekly working hours and exceptions; project settings (`timeZone`, `calendarId`, `startDate`, `hoursPerDay`,
  `daysPerWeek`, `daysPerMonth`, `weekStartsOn`).
- Transactions on tasks, dependencies, calendars and settings, validated before anything changes, with a patch and
  its inverse as the result. `applyPatch(data, patch)` applies a patch to stored data.
- Automatic scheduling (as soon as possible), "start no earlier than" constraints (set when an automatically
  scheduled task is dragged), manually scheduled tasks, roll-up of parents, and cycle detection.
- `onChange` with `source`: `'load'`, `'edit'`, `'undo'` or `'redo'`.

**View**

- A task list with expand and collapse, configurable `columns` (built-in ones and your own with a `value` function)
  and virtualized rows, tried with 10 000 tasks.
- A time axis with seven presets from `'hourAndDay'` to `'manyYears'`, custom presets, header labels in any `locale`,
  and ISO week numbers.
- Task bars with progress, summary bars for parents, milestones, dependency arrows, a today line and shaded
  non-working time.
- A divider between the task list and the timeline that can be dragged, moved with the arrow keys and reset with a
  double-click, with `listWidth` and `onListWidthChange` to keep the width.

**Interaction**

- Drag bars to move them, drag their end to resize, drag the progress, draw bars for unscheduled tasks, and drag
  from a bar's end to another bar to link them. Snapped to the preset's time resolution, with auto-scrolling at the
  edges.
- `validateChange` to refuse a drag, with a message shown while dragging.
- Cell editing (double-click, Enter or F2) with native date fields and durations like `4d` or `2w`.
- A task editor dialog with general fields, predecessors, successors and advanced settings.
- Context menus on tasks (add, indent, outdent, convert to milestone, delete) and on the time axis (zoom), which you
  can extend with `taskMenuItems` and `timeAxisMenuItems`.
- A task tooltip, with its content replaceable through `renderTaskTooltip`.
- Selection with click, Ctrl/Cmd-click and Shift-click, keyboard navigation, Delete, and undo and redo of the last
  100 changes.
- Every interaction can be turned off, e.g. `taskDrag={false}` or `cellEdit={false}`.

**Look and platform**

- One stylesheet, themed with `--qz-*` CSS variables, and a dark theme with the `qz-dark` class.
- Server rendering: with an explicit `locale` and time zone the server renders the chart, otherwise an empty frame
  that fills in when the page hydrates.
- Both packages are ESM only, ship their TypeScript source with declaration maps, and `@quartzio/gantt` has no
  dependencies.

Not in this release yet: constraint types other than "start no earlier than", scheduling backwards from the project
end, the critical path, baselines, resources and assignments, and wrappers for frameworks other than React.

## Upgrading

The packages are new. Install both, and keep them at the same version: `@quartzio/gantt` is a peer dependency of
`@quartzio/gantt-react`.

```bash
npm install @quartzio/gantt-react @quartzio/gantt
```

The [API reference](https://github.com/Sindreglo/quartzio/blob/main/packages/gantt/API.md) lists every option.
